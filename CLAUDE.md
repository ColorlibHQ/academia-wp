# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**Academia 1.0.4** is a Colorlib **WordPress block theme** (Full Site Editing) for
education sites, plus a companion plugin. 53 patterns, 18 templates, 8 colour
palettes × 5 typography presets, 6 one-click starter sites, text domain
`academia`. It is **not** a static HTML template — the Colorlib R2
preview/download flow and the HTML-template upgrade phases in the global
instructions do not apply here.

It was built from the Academia HTML template (EDD 41420,
`preview.colorlib.com/theme/academia/`), which is a Bootstrap 5 static site. The
design was **rebuilt, not ported**: the template's identity colour and its
subject matter were kept, its measurements, type scale and page structure were
not. See "What changed from the HTML template" below.

Distribution is **outside WordPress.org** — `Update URI` in `style.css` points at
`updates.colorlib.com`, the same model as Unapp. Three Theme Check REQUIRED
findings are the direct and intended consequence of that; see "Theme Check".

Requires WP 6.6+; tested on WP 7.0/7.1. **No build step, no npm, no SCSS** —
every file is committed as-is.

## Commands

```bash
# Regenerate the design system (theme.json + every styles/*.json)
python3 .dev/build_theme.py

# Regenerate patterns
python3 .dev/batch_sections.py     # the 20 education sections
python3 .dev/batch_pages.py        # page starters, demo homes, footers
python3 .dev/batch_course.py       # course single + archive headers
python3 .dev/grounds.py            # assign section grounds, then audit them

# Lint everything
find . -name '*.php' -not -path './.git/*' -exec php -l {} \; | grep -v "No syntax errors"
for f in theme.json styles/*.json styles/colors/*.json styles/typography/*.json; do \
  python3 -c "import json;json.load(open('$f'))" || echo "BAD $f"; done
for f in assets/js/*.js plugin/academia-library/assets/*.js; do node --check "$f"; done

# Contrast check (the palette was designed against it)
python3 .dev/contrast.py "#0f766e:#ffffff" "#ffffff:#0f766e"

# Build the distributable zips (theme and plugin separately)
sh .dev/build-zip.sh /tmp/academia-build

# Translation templates
wp i18n make-pot "$PWD" "$PWD/languages/academia.pot" --exclude=.dev,plugin --domain=academia
wp i18n make-pot "$PWD/plugin/academia-library" "$PWD/plugin/academia-library/languages/academia-library.pot" --domain=academia-library

# Screenshot (1200x900 exactly — Theme Check rejects anything else)
node .dev/screenshot.mjs <path-to-playwright-index.js> http://local-wp.local/ screenshot.png
```

**Local testing** uses the Local site `local-wp` (see the `local-wp-testing`
memory for the wp-cli invocation). Symlink both parts:

```bash
ln -sfn "$PWD" "/Users/silkalns/Local Sites/local-wp/app/public/wp-content/themes/academia"
ln -sfn "$PWD/plugin/academia-library" "/Users/silkalns/Local Sites/local-wp/app/public/wp-content/plugins/academia-library"
```

⚠ **`local-wp` is a shared test site and something else rotates its active
theme.** During this build it flipped to pinbin, travelify and sparkling
unprompted, which silently invalidated two screenshots and made the demo
importer look broken (it degrades when Academia is not active — correctly).
**Never trust a capture you did not verify.** Activate, assert, capture, assert
again, in one shell invocation:

```bash
for attempt in 1 2 3 4 5; do
  wp theme activate academia >/dev/null 2>&1
  curl -s http://local-wp.local/ | grep -q "themes/academia/style.css" || continue
  node .dev/screenshot.mjs ... && curl -s http://local-wp.local/ | grep -q "themes/academia/style.css" && break
done
```

## Architecture

### Where things live

| Concern | File(s) |
| --- | --- |

| Section styles (`card`, `card-flat`, `section-soft`, `section-dark`, `section-gradient`, `elevated`, `outline`, `highlight`) | `styles/*.json` with `blockTypes` |

| Header/footer | `parts/*.html`, each a single `wp:pattern` ref so the text is translatable |
| Sections, page starters, demo homes, footers, hidden partials (53) | `patterns/*.php`, all generated by `.dev/batch_*.py` |
| **Course data, read from any source** | `inc/courses.php` |
| Front page + Blog page on activation | `inc/front-page-setup.php` |
| 6 starter sites | `inc/starter-sites.php` |
| Form-plugin detection (10 recognised) | `inc/forms.php` + `assets/css/forms.css` |

| Plugin recommendation notice | `inc/plugin-notice.php` |

### The course architecture — read this before touching courses

**A theme must not register a post type.** `inc/courses.php` only *reads*, through
an adapter layer, and resolves one source per request in priority order:

1. `academia_course` (the companion plugin) — the full meta set
2. Tutor LMS / LifterLMS / Sensei / LearnDash — mapped onto the same shape
3. plain posts in a `courses` category — the no-plugin fallback

Everything renders through `academia_course_card()`, so one design covers all
five sources. Add a source via the `academia_course_sources` filter. Detection
prefers a **registered post type** over a class name, because plugins move their
namespaces between versions and the post type does not — except LifterLMS and
Sensei, which both register `course`, so a class check breaks that tie.

**Dynamic sections must be shortcodes, never inline PHP.** This is the single
most important constraint in the theme. A pattern file's PHP runs when the
pattern renders *from the file*, but `inc/front-page-setup.php` and the starter
sites **expand** patterns into real post content so the copy is editable — and
PHP inside stored content never runs. During this build the course grid was
inline PHP, got expanded at activation before any course existed, and froze
`"No courses yet"` into the home page permanently. `[academia_courses]` and
`[academia_course_browser]` exist for exactly this reason.

**…and shortcode blocks need a filter to work in templates.** `core/shortcode`'s
render callback only calls `wpautop()`; the expansion is done by `do_shortcode`
on `the_content`, which does not run for a block template. So
`academia_render_shortcode_block()` in `functions.php` applies `do_shortcode` to
`render_block_core/shortcode`. Without it the course archive template renders
the literal text `[academia_course_browser]`. `do_shortcode` on already-expanded
output is a no-op, so applying it unconditionally is safe.

**The course browser is progressive enhancement, not the Interactivity API.**
The server renders the complete, correct result for whatever is in the query
string; `plugin/academia-library/assets/filter.js` (~70 lines, no dependencies)
intercepts the form, fetches that same URL and swaps the results region. The
Interactivity API's directives are only worth their weight behind a bundler, and
this theme has no build step. Verified: JS on → 0 document navigations; JS off →
still filters correctly with the submit button visible. The button is in the
markup and hidden by `.is-enhanced`, added by the script — that ordering is what
keeps the no-JS path working.

## Conventions that matter

- **Section wrapper**: every section is `wp:group {"align":"full","layout":{"type":"constrained"}}`
  with **top/bottom padding only**. `useRootPaddingAwareAlignments` is on, so an
  alignfull constrained group gets its left/right padding from root padding;
  adding L/R padding double-pads.
- **`sp()` refuses spacing off the scale.** theme.json registers slugs 20–80 in
  tens only. `var(--wp--preset--spacing--16)` is undefined, so WP drops the
  declaration and the element silently falls back to its inherited gap. The
  scale is fluid from 50 up (`clamp()`), so one value covers phone to desktop.
- **Colours in patterns are palette slugs only**, so the eight colour variations
  restyle everything.
- **Never name a palette slug after a core utility class.** WordPress emits the
  bare class `has-border-color` on any block with a custom border colour, and a
  palette slug named `border` makes that class *also* set text colour — the
  course price rendered in `#dde7e5` until the slug was renamed to `divider`.
  The same trap waits for `text`, `background` and `link`.
- **Block style variations live in `style.css`, not behind a `style_handle`.**
  `register_block_style( …, 'style_handle' => … )` only enqueues while WordPress
  serves separate core block assets, and any plugin can switch that off
  site-wide — WooCommerce does on the test site. Every variation silently lost
  its CSS while still rendering its class. `style.css` always loads.
- **A wide wrapper around raw HTML needs `layout: default`, not `constrained`.**
  A constrained layout caps its direct children at `contentSize`, and HTML from a
  shortcode carries no alignment class to escape it — the course grid rendered
  780px wide inside a 1240px `alignwide` group until the wrapper became flow.
- **Bind a toggle class to exactly one element.** `academia-scheme-toggle` was on
  both the `wp:buttons` wrapper and the `wp:button`; the script binds every
  element carrying the class, so one click toggled twice and landed back where it
  started. The class must be on the **button**, which is also what
  `render_block_core/button` detection needs.
- **Assign counts to a variable before a translation call.** Theme Check parses
  these statically and reads `$course['lessons']` inside `_n()` as a text domain,
  reporting domains called `lessons`, `reviews` and `total`. Extracting the count
  first removed five messages.
- **Fonts**: six self-hosted variable families in `assets/fonts/`, two
  `@font-face` per weight per subset (latin + latin-ext). The `heading` and
  `body` slugs carry the faces; typography presets redefine those slugs, so every
  pattern follows without touching a pattern file.
- **Style variation partials are all-or-nothing.** The Site Editor lists a
  variation under Colors or Typography only if it contains *nothing else*. A
  stray `settings.shadow` in a colour partial demotes it to a full variation —
  which is why shadows live in `theme.json` and are built with `color-mix()` on
  palette colours so they follow the active palette.
- **theme.json nested `css` strings**: WP splits on `&`, so `& a, & b{…}` breaks.
  One `&` rule per selector.
- **Root padding values need units** (`"0px"`, not `"0"`): WP 7.0's navigation
  overlay uses `clamp(1rem, var(--wp--style--root--padding-top), 20rem)`, and a
  unitless `0` invalidates the whole declaration, losing the mobile menu's
  padding.
- **Buttons take `primary` as their ground and `base` as their text**, radius
  12px — squarer than Unapp's pills, which is what separates the two themes at a
  glance. In a **dark** palette `contrast` is light, so those variations set the
  button text to `contrast` instead or it is light-on-light.
- **Dark mode lifts the palette, it does not replace it.** `assets/css/scheme.css`
  computes the lifted colours on `html` and consumes them on `body`: doing both
  on one element makes each custom property depend on itself, which is invalid
  and silently dropped.
- **No orphaned grid rows.** WP's grid layout keeps one column count at every
  width, so use the `academia-grid-2/3/4` utilities alongside `columnCount`; they
  step down through counts that divide the item count evenly. The subject grid is
  nine tiles precisely so 3 → 2 → 1 all divide.
- **Patterns are generated, not hand-typed.** Extend `.dev/pgen.py` (shared
  emitters) or `.dev/acomp.py` (education components — course cards, curriculum,
  instructors, plans, stats) and re-run the batch, rather than writing markup by
  hand. Serialized classes and styles must match what the block's `save()`
  produces or the editor reports invalid content.
- **Section grounds alternate, and `.dev/grounds.py` enforces it.** Sections
  declare a *role*; the ground is derived from the role plus position. The first
  cut put **five** sections in a row on the page ground, which is exactly why
  the page read as one undifferentiated column. Run it after any batch and after
  changing a composition — it fails on two consecutive sections sharing a
  ground, two adjacent full-bleed bands, or a six-plus-section page with no band
  at all. Never hand-set a ground on a section pattern; add it to `ROLES`.
- **Group inside a card; do not space evenly.** A flat run of children with one
  uniform `blockGap` makes every element equidistant, so nothing reads as
  belonging together — that was the "hard to tell where one thing ends" problem
  *inside* the cards. `.academia-card` is three groups: identity (tight),
  facts (tight, takes the free space), and a hairline-separated foot.
- **A hairline has to be visible to do its job.** `#dde7e5` was 1.26:1 on white
  — an edge nobody can see, so a grid of cards read as floating text. `divider`
  is `#c3d3cf` (1.55:1). Card outlines are decorative, so the AA text threshold
  does not apply; ~1.5:1 is what registers as an edge.
- **One design per component.** A `courses-showcase` pattern with hand-built
  static cards was deleted rather than restyled: two card designs that must stay
  in visual sync is how inconsistency starts. The dynamic grid plus the plugin's
  demo importer covers "a site with no courses yet".
- **Never rely on "plugins load before the theme" to pick between two
  declarations of the same function.** It is true for an ordinary request and
  false for plugin *activation*, where the theme is already loaded — the theme
  and plugin both declared `academia_course_filter()` and activating the plugin
  fataled with "Cannot redeclare", so the companion plugin could not be turned
  on at all. The theme owns the entry point; the plugin swaps behaviour through
  `academia_course_filter_renderer`. **Test plugin activation with the theme
  already active** — activating the plugin first hides this entirely.
- **`.wp-site-blocks` applies the root `blockGap` between the top-level
  regions.** It is a flow container, so header, main and footer each get a
  `margin-block-start` — a 20px strip of page background that is invisible next
  to a white section and an obvious white band where the gradient CTA meets the
  dark footer. `style.css` zeroes it; sections supply their own padding.
- **Every content template is 70/70, matching `SECTION_PAD`.** They arrived
  from Unapp on 60/70 — opening 64px tight and closing 96px loose — so a blog
  or search page opened on a different rhythm from every section under it. If
  you add a template, use 70/70.
- **A `wp:list` with no class inherits the browser's bullets and 40px indent.**
  The footer's three link columns shipped like that — bulleted, indented lists
  on a dark ground, and the single thing that made the footer look unfinished.
  Any list the theme styles itself needs a real class.
- **A flow-layout column's `blockGap` does nothing once you reset child
  margins.** WordPress spaces flow children with `margin-block-start`; the
  footer's `margin: 0` resets overrode it, so the brand column's children sat
  1px apart. Use an explicit `layout: flex` with a gap where the spacing
  matters.
- **Keep a starter's CTA default in sync with `patterns/header.php`.**
  `academia_apply_starter_header()` compares against a literal; when the header
  label changed and the literal did not, every starter wrote a header override
  it did not need.
- **Every niche owns its whole page.** A starter must not borrow a section whose
  copy is written for another kind of site. ⚠ **Currently violated**: all six
  demo homes open with `hero-academy`, whose copy is written for the online
  academy. Each vertical needs its own `hero-{niche}` and its own proof/FAQ/CTA
  copy — the highest-value outstanding work.

## Theme Check

Run it on the **built** theme, not the working tree — `.dev/` and `plugin/` are
excluded from the zip and would otherwise report plugin-territory findings for
code users never receive:

```bash
sh .dev/build-zip.sh /tmp/academia-build
cp -R /tmp/academia-build/academia "$SITE/wp-content/themes/academia-dist"
wp theme-check run academia-dist    # the theme-check plugin does have a CLI
```

Three REQUIRED findings are expected and intended:

| Finding | Why it stands |
| --- | --- |
| `Update URI` in style.css | Required *by* distribution outside WordPress.org. Theme Check flags it precisely because it means "not in the directory". |
| `add_shortcode()` in `inc/courses.php` | The only mechanism that survives a pattern being expanded into post content. See the course architecture above. |
| Reference to unsplash.com | The photographs come from the Academia HTML template Colorlib already sells with them. The Unsplash Licence permits commercial use and redistribution but is not GPL, so wp.org would reject it. |

`accessibility-ready` is self-asserted, not the result of a wp.org
accessibility review: contrast (AA in both schemes), focus-visible rings,
`prefers-reduced-motion`, `aria-pressed` on the scheme toggle and `role="status"`
on the result count were all verified locally.

## What changed from the HTML template

Worth knowing, because the template is still sold and the two now differ:

- **The palette fails WCAG AA and was rebuilt.** `#1eb2a6` is **2.63:1** on white
  — failing as text and as a button ground — and the body copy was `#999` on
  `#f8f8f8` at **2.68:1**. `primary` is now `#0f766e` (5.47:1 both ways) and
  `#1eb2a6` survives as `teal-light`, for large decorative fills only.
- **The hero** was a ~900px teal cover with the copy stranded bottom-left of an
  empty field; it is now a split with the claim in a readable column.
- **The courses page** had nine identical cards (seven said "Introducing to
  Programming with WordPress"), no filter, no search, no sort, and the page title
  set in white across a face. It is now a filtered, searchable, sortable archive.
- **The subject grid** was eleven tiles six-across — five orphans on the last row
  — every one labelled "25 Courses". Nine tiles now, three-up.
- **Dependencies dropped**: AOS (replaced by CSS `animation-timeline`),
  tiny-slider (native scroll-snap), GLightbox (core's lightbox), Leaflet.
- **Kept**: the teal identity, the education subject matter, and the photographs.

## Release checklist

1. `php -l` all PHP, validate all JSON, `node --check` all JS.
2. Regenerate anything whose generator changed; confirm no spacing slug, font
   size or palette slug is off-scale (see the sweep in Commands).
   Run `python3 .dev/grounds.py --audit` — it must report 0 problems.
3. Bump `Version:` in `style.css`, `Stable tag:` in `readme.txt`, and the plugin
   header if it changed. Add a CHANGELOG entry.
4. Activate on `local-wp` (asserting the theme sticks), load `/`, the course
   archive, a single course, `/blog/`, a post, an author/category/tag/date
   archive, `?s=`, and `/shop/` if WooCommerce is active.
5. Render every pattern server-side and check `debug.log`:
   `wp eval 'foreach ( WP_Block_Patterns_Registry::get_instance()->get_all_registered() as $p ) { if ( strpos($p["name"],"academia/")===0 ) do_blocks($p["content"]); }'`
6. Confirm the course filter both ways: with JS (0 document navigations) and with
   JavaScript disabled (still filters, submit button visible).
7. Theme Check the built theme; expect exactly the three findings above.
8. Regenerate `languages/*.pot` and `screenshot.png` (1200×900) if strings or the
   hero changed.
9. `sh .dev/build-zip.sh` — it fails if the theme zip contains `plugin/`.
